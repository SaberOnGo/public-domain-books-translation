EPUB 生成后做分层随机抽检。抽检发现任何 P0/P1/P2 或系统性风险，就归纳问题族，用 rg、术语表、脚本和局部 agent 审计查全书同类问题。

质量维度怎么覆盖
你列的维度可以这样分层处理：
忠实度：每章源文对照全量复检负责主覆盖；随机抽检只做发布前再验证。
中文顺读、过硬/过直/过板、英文句法残留：先做中文独立阅读，不看原文，专查断气长句、清单句、翻译腔；再回到原文确认润色没有改错。
教学节奏：适合非虚构、科学、历史书，按“概念引入、例子、推理链、读者负荷”检查，不要只看句子。

案例译名、人名、地名、书名、船名、机构名：建立专名 ledger；标题里的出现不算正文首次出现，首次注释放正文自然出现处。
标题与小标题：按 nav title、display title、subtitle 分开，不把纸书长标题链塞进 EPUB 目录。见 chapter_title_policy.md (line 1)。
过度解释或加戏：对高画面、高情绪、高论证段做源文对照，检查是否新增了原文没有的比喻、动作、心理判断或解释。
你没提到但必须管的：版权/来源证据、metadata/frontmatter、注释密度、读者可见 AI/制作痕迹、乱码/异常空格、旧纸书目录残留、图表/公式/注释层、EPUB XHTML/nav/mobile 阅读效果。
低 token 关键
省 token 的核心不是少检查，而是“不要让 agent 盲读全书”：
用脚本先抽样、分层、生成样本和证据。
用 rg 先扫术语、裸外文、禁用写法、异常标点、长句、可疑括注。
每次只把命中的片段、对应源文、术语记录交给 agent。
把问题归为问题族后，用检索式全书找同类，而不是让 agent 自己凭记忆翻全书。
后期随机抽检只做发布置信度和系统性问题发现；真正的翻译质量应在每章生产时解决。
所以，本项目最好的策略不是“分层随机抽检”或“每章全量复检”单独胜出，而是：章节全量复检防止坏译文进入终稿；
分层随机抽检发现系统性盲点；问题族审计用低 token 方法追全书同类问题。
当前仓库方向是对的，下一步最值得优化的是把问题族审计做得更脚本化、更少依赖 agent 全书阅读。”
